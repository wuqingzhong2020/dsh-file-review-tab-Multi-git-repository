# 非 Git 目录审查

v0.3.2 固定依赖管理插件 v0.1.2。管理页、配置、类型判定、发现与文件归属均由管理插件提供；本插件使用其批量 Host 归属接口，适配会话差异、Git 比较、可信生命周期、定位和撤销／重新应用。

## 操作

在右侧「多代码仓管理」Tab 添加条目，类型选择「非 Git 目录」，填写名称并选择目录后保存。也可填写发现容器，点击「预览发现结果」，逐项添加后保存。工程内目录持久化为相对路径；工程外目录只在当前会话临时使用。旧 v1 配置无需重建，首次新增普通目录自动升级到 v2 并保留 `.v1.bak`。

文件审查标题保持「文件审查（多git仓）」。筛选包含「全部 Git 仓库」、单 Git 仓、「全部非 Git 目录」、单普通目录和有历史记录时的「归属待处理」。混合工程默认全部 Git，纯普通目录默认全部非 Git 目录。全部 Git 在会话范围同样排除普通目录与未纳管文件。

普通目录支持上一轮、本会话、待确认。未暂存、已暂存、未提交、已提交和分支均禁用；从 Git 范围切入普通目录时，恢复上次会话范围，初始为本会话。切换时不显示 Git 提交或分支选择。

搜索、差异布局、展开、复制、评论沿用会话审查。统计、批量复制、撤销和确认仅作用于显示范围。深链先定位文件归属，再选择范围和展开；未纳管文件只展示历史内容，不能打开、定位或修改。普通目录不会因为没有 Git 基线而生成全目录差异，只显示已有工具变更记录。

## 确认与历史

按钮「确认当前范围 N 个文件」按每个文件当前变更修订保存进度。隐藏文件保留待确认；后来改动或补录的新文件只重新打开对应文件。旧整轮 r1 决策仅在完整轮次修订仍一致时展开；不匹配时全部待确认。确认不改代码、不提交 Git、不清空评论。

普通目录嵌在父 Git 仓中时形成独立边界，父仓 Git 比较和按需差异排除它。不可用子目标、未加入的发现候选、未声明的更深 Git 根目录、`.git` 元数据和逃出根目录的链接不会回退到父仓授权。类型转换不改写历史评论与记录来源。

## 代码入口

`review-target-selection.ts` 定义统一选择模型，`use-target-ownership.ts` 按会话、工作区修订和文件集合隔离异步请求，`review-confirmations.ts` 维护按文件决策。`FileReviewService` 对实际读写重新校验所有权，`lifecycle-capture.ts` 在执行前和接受前检查，`git-review.ts` 在普通文件读取及差异加载前排除其他目标。

验证包含实际 Git 夹具中的普通目录撤销／重新应用、父仓比较去重、未知组件拒绝、外部会话隔离、旧确认迁移及中英文浏览器交互。实际 Desktop 的安装与界面结果记录在双插件验证文档中。
